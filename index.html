Brain Plugins

Two Claude Code plugins that make an agent work the way Andrej Karpathy or Matt Pocock builds and teaches. Each one ships the person's 7 rules, a skill that grades the agent against them, and a wiki of their public work where every claim stands on a verbatim, linked quote.

karpathy-brainpocock-brain

Neither Andrej Karpathy nor Matt Pocock made, reviewed or endorsed these plugins. They are built only from what each of them published.

The unit of evidence

Every claim carries its quote

The wikis follow Karpathy's own LLM-wiki pattern: raw sources that never change, plus wiki pages that an LLM writes and maintains. One rule holds the pages together: no claim without a quote directly under it. Each quote line names the raw file it came from, links to the public original and carries the month it was said.

Teaching is building ramps. He builds live, from an empty file, one step at a time. > "In my mind, education is the very difficult technical process of building ramps to knowledge." — [youtube-appearances/…summoning-ghosts.md](youtube.com/watch?v=lXUZvyajciY&t=7401s) · 2025-10

A checker script confirms every quote word for word against the raw files. A separate claim check then asks whether the quote supports the claim, whether this person said it, and whether the date is right.

The 7 rules

Each rule appears in at least two different kinds of source, such as a post and a talk, and in the person's own words. The agent follows them, and the teach skill grades against them.

Karpathy

  1. Rebuild it to understand it. Read or write the smallest version of anything you rely on. Never explain code you haven't read.
  2. Look at the data and predict the number. Write down the expected output, then run it and compare.
  3. Build up from something you trust. Start from the simplest working version and check after every change.
  4. Make complexity earn its place. Fewer files, dependencies and abstractions. Say what you left out.
  5. Small diffs, and you own them. One concrete change at a time, and never "it works" without a run.
  6. Build it live, as the smallest complete version. Teach with a minimal, runnable example, built step by step.
  7. Build the ramp, then let the learner climb. Each step needs only the earlier ones; learners get an exercise first.

Pocock

  1. Align before any code. State the goal, assumptions and scope; ask about decisions that change the result.
  2. Build the feedback loop first. Decide how you'll know it works, run it, go red to green in thin slices.
  3. Give the agent less. Read only what the task needs and make the smallest change that works.
  4. Design the interface, delegate the implementation. Signatures, inputs, outputs and layout come first.
  5. Problem first, solution after. Show the failing case before the fix; learners try an exercise first.
  6. One thing at a time, in dependency order. One idea per step, pitched at the user's level.
  7. Use what has always worked. Proven techniques and boring tools. No hype, and say when you're unsure.
/karpathy-brain:teach <task>

What happens on a teach run

  1. The skill hands your task to the persona agent unchanged, plus any file paths or decisions from your conversation.
  2. The agent must read wiki/hot.md before it can use any other tool. wiki_budget
  3. It may open at most 5 wiki pages in total, chosen from links in hot.md. It can't grep the wiki to get around the limit. wiki_budget
  4. It does the task by the 7 rules and ends with three lines: Ran, Came out, Changed.
  5. It can't finish until that block is there and every mention of the person cites a wiki page that exists. footer_check
  6. The skill grades each rule PASS, PARTIAL, FAIL or N/A, with a short quote from the answer as evidence. It checks the footer and the citations with tools, and re-runs the cheapest test.
  7. Any FAIL gets one revision round with the exact fix, never more. Then you see the unedited answer and the grade table.
  8. If the turn wrote code and nothing ran afterwards, the session can't end until something runs. The message is "Karpathy rule, run it before you say it works." run_check
hooks/hooks.json

The three guards

ScriptEventWhat it blocks
wiki_budget.pyPreToolUseAny tool before hot.md is read, a 6th wiki page, and grep or Bash over the wiki. It acts only inside the persona's own subagent.
footer_check.pySubagentStopFinishing without Ran / Came out / Changed, naming the person without a citation, or citing a page that doesn't exist.
run_check.pyStopEnding a persona turn where code was written but nothing was run afterwards. It fires once, so it can't loop.

The scripts use only the Python standard library, so you need python3 on your PATH.

The claim check is the step that matters most. Checking a quote word for word only proves that it exists. It doesn't prove that the quote supports the claim, or that the person said it. On the Karpathy wiki the check found:

Install

Add the marketplace, then pick a brain

/plugin marketplace add jankutschera/brain-plugins
/plugin install karpathy-brain@brain-plugins
/plugin install pocock-brain@brain-plugins

Then hand it a task:

/karpathy-brain:teach Write a numerically stable softmax in numpy and show why it is stable
/pocock-brain:teach Add a typed retry helper with a test that proves it retries

Limits

What these plugins are not

  • They're not the person. The agent follows rules taken from their public work and cites where each rule comes from. Where the wiki is silent, it says nothing about them.
  • They're snapshots. Both wikis were frozen in October 2026, so anything published later isn't in them.
  • The grade is a second opinion from the same model, and it can be strict. In one test it gave 4 of 7 because an exercise answer was wrong, and it was right.
  • Quotes remain the work of the people quoted. Each one is short, attributed and linked to its public source.
